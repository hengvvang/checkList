`git push` 是将本地仓库的提交推送到远程仓库的核心命令。掌握它的各种用法，能够让你在日常开发、多分支管理以及开源协作中游刃有余。

以下是 `git push` 的所有主要用法和常见场景解析：

---

### 一、 基础用法

* **`git push <remote> <branch>`**
* **作用**：将本地指定分支推送到远程仓库的对应分支。
* **示例**：`git push origin main`（将本地 `main` 分支推送到远程 `origin` 的 `main` 分支）。


* **`git push`**（直接运行）
* **作用**：如果当前分支已经与远程分支建立了追踪关系（Tracking），直接输入 `git push` 即可将当前分支推送到对应的远程分支。



---

### 二、 简化与关联选项

* **`-u` 或 `--set-upstream**`
* **作用**：首次推送时使用，将本地分支与远程分支进行关联。关联后，后续直接执行 `git push` 或 `git pull` 即可，不需要再指定远程和分支名。
* **示例**：`git push -u origin feature-login`


* **`-f` 或 `--force**`
* **作用**：**强制推送**。如果本地版本与远程版本有冲突（例如执行过 `git reset` 或 `git commit --amend` 改变了历史），直接推会被拒绝，使用 `-f` 会用本地历史**覆盖**远程历史。
* ⚠️ **注意**：团队协作中慎用，容易覆盖掉队友的代码。


* **`--force-with-lease`**
* **作用**：更安全的强制推送。它会先检查远程分支是否被其他人悄悄修改过，如果别人推送过新代码，它会拒绝推送，防止覆盖他人的工作。**强烈推荐代替 `-f`。**



---

### 三、 删除与重命名远程分支

* **`git push <remote> --delete <branch>`**
* **作用**：删除远程仓库上的指定分支。
* **示例**：`git push origin --delete old-feature`


* **`git push <remote> :<branch>`**
* **作用**：另一种删除远程分支的写法（把一个空分支推送到远程，等同于删除）。
* **示例**：`git push origin :old-feature`



---

### 四、 推送标签（Tags）

* **`git push <remote> <tagname>`**
* **作用**：推送指定的本地标签到远程。
* **示例**：`git push origin v1.0.0`


* **`git push <remote> --tags`**
* **作用**：将本地所有**未被推送到远程的标签**一次性全部推送到远程仓库。



---

### 五、 高级选项

* **`--all`**
* **作用**：将本地所有分支一次性推送到远程仓库。


* **`--mirror`**
* **作用**：将本地所有分支、标签和引用全部镜像推送到远程仓库（通常用于仓库迁移）。


* **`--dry-run`**
* **作用**：模拟推送（演习），不会真正执行推送，但会告诉你这次推送会发生什么。



---

> > 💡 **最佳实践**：在多人协作时，日常开发多用 `git push`（前提已通过 `-u` 关联），遇到历史重写需要强制推送时，优先使用 `git push --force-with-lease`。
